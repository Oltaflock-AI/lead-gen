01 · North star

One operator runs this app. Every page should feel like a Notion page: generous whitespace, modular blocks, soft borders, no decoration that doesn't earn its keep. Buttons are quiet by default; the page does the talking. The aesthetic is calm, editorial, off-white — not corporate SaaS.

Modular

Every page is a stack of self-contained blocks. Reorderable mentally, even if not literally. No giant forms.

Quiet

Off-white canvas, hairline borders, one accent color. Type carries the hierarchy, not boxes-within-boxes.

Operator-first

Built for one person doing the same five tasks in a loop. Optimize for repetition, not first impressions.

02 · What's getting cut

The current app has three things that don't pay rent. Remove them, don't redesign them.

✕

Manual revenue override (Close rate %, Average deal value $) on Settings — gone. The AI forecast is independent and the override panel adds noise without value.

✕

AI revenue forecast tile on Dashboard — gone. Replace the slot with something the operator actually checks: today's outreach throughput.

✕

"+ Asana task" button in the global header on every page — gone. Asana stays as a connection, but the global affordance is clutter. Move task creation into context (e.g. on a lead row).

03 · The pipeline

Five steps, in order. The sidebar mirrors this order so the operator walks top-to-bottom every session.

01
Scrape
Country + niche + filters → CSV of leads.
02
Offers
One offer per niche. Feeds the AI writer.
03
Leads
Browse CSVs. Score, dedupe, qualify.
04
Outreach
AI-personalized first send via Resend.
05
Sequences
4-step cadence: cold → bump → Loom → breakup.

Dashboard sits above this loop as a pulse-check. Settings sits below as plumbing.

Spacing & radius

Page padding 32px desktop, 16px mobile. Block internal padding 22–26px. Radius scale: 6 / 10 / 14 / 20. Hairline borders 1px solid #E8E5DC instead of shadows.

Iconography

Use Lucide at 16px line weight, stroke="1.5", color var(--ink-mute). Never filled. Each nav item gets one icon; no decorative icons inside copy.

Motion

  • Hover: 120ms ease on background & border.
  • Page transition: none. This is a tool, not a marketing site.
  • Toasts: slide-up 180ms, auto-dismiss 4s.

Sidebar rules

  • Three sections, in order: Pulse (Dashboard), Pipeline (Scrape → Offers → Leads → Outreach → Sequences), System (Settings).
  • Active item gets the sunken background + ink-color text. No left bar, no glow.
  • Counts (e.g. "12") only appear when there's something pending. Hide the badge at zero.
  • Connection status block lives at the bottom of the sidebar, always visible. Green dot = connected, hollow circle = off. No "on" pills — they read as buttons.
  • Workspace switcher (top): logo + name + subtitle. Click opens a menu (future-proofing).

Top of main area

  • Crumb: workspace / page-name in mono, 11px, mute color. No "Workspace /" prefix repetition — just lowercase.
  • Page title in Fraunces 26–32px. No "+ Asana task" button on the right anymore.
  • Subtitle in 13px ink-mute. Where useful, dynamic ("47 emails queued" beats "Pipeline value, lead quality, and outreach activity").
  • If a page has a primary action (e.g. "Run search", "Save offer"), it lives inside the relevant block, not in the page header.

06 · Component library

Buttons

Primary = ink fill, used once per page-section max. Default = white surface, hairline border. Ghost = transparent, for tertiary actions like "Cancel" or "Clear". Padding 6px 12px, radius 6px, font-size 13px, weight 500.

Inputs & fields

Labels are uppercase 11px with letter-spacing: 0.08em. Inputs have no shadow, just a hairline border that darkens on focus to --ink. Placeholder is --ink-faint.

Tags / status pills

Draft Sent Queued Opened Replied Bounced
Pill shape, soft tinted background, no border on colored variants. Used for status only — never as nav, never as button.

Block

The fundamental unit. A block is a white surface, hairline border, 14px radius, 22–26px padding, optional h5 header with a small green dot. Pages stack 3–6 blocks vertically with 18–24px gap.

Block header

Body content. Could be a form, a table, a stat row, or a list. Keep blocks single-purpose — if you find yourself adding a divider inside a block, it's two blocks.

07 · Page · Dashboard

/  ·  "Pulse"

07
Dashboard
/

The morning glance. What did yesterday do, what's queued today.

Blocks (top to bottom)

  1. Stat row — 4 cards: Total leads, Qualified, Sent today, Replies. Each card shows the number (Fraunces 28–32px) + a one-line context delta in 11px mute. No more "AI revenue forecast" tile.
  2. Today's queue — list of emails scheduled for the next 24h, grouped by step (cold / bump / Loom / breakup). Empty state: "Nothing queued. Load a CSV from Outreach."

Cuts vs current

  • Remove the "AI revenue forecast" block entirely.
  • Remove "AVG QUALITY (weighted)" — operator never references it.
  • Keep Per-CSV breakdown but collapse by default with a "Show breakdown" toggle.

10 · Page · Offers

/offers  ·  "What you sell"

10
Offers
/offers

Currently the form sits above an empty list. Flip the priority: list of offers first, "+ New offer" button opens a modal or expanding block.

Layout

  1. Header strip: page title + subtitle + a "+ New offer" primary button on the right.
  2. Offer cards grid: 2 columns on desktop, 1 on mobile. Each card shows: niche (Fraunces 18px), one-line offer summary (truncated to 140 chars), Loom thumbnail/link icon, last-updated mute timestamp. Hover reveals Edit / Duplicate / Delete in the top right.
  3. New / edit offer drawer (slides in 520px from right): the form fields exactly as today (Niche, Loom URL, The offer, Tone notes), but in the drawer instead of a sticky top form. Save / Clear at the bottom.

Why this is better

  • The empty form was visually loud and only used once per niche. Hiding it removes 60% of the page weight.
  • An offer is a saved object, not a form — designing it as a card matches that mental model.

14 · Implementation notes

Stack assumptions

  • The current app is Flask-rendered HTML based on the URL bar (localhost:5001/scrape). The redesign is templating-agnostic — drop in new Jinja templates + a single CSS file.
  • If you (or Claude Code) want to migrate to React, fine, but it's not required. The visual system holds either way.

File structure suggestion

static/
├── css/
│   ├── tokens.css         ← all CSS vars from §04

│   ├── components.css     ← btn, input, tag, block, table, callout
│   └── shell.css          ← sidebar, main, header

Order of operations for Claude Code

  1. Add the three font links + tokens.css globally. Reload — every page should now have the right type and color baseline even before refactoring.
  2. Build _shell.html with the new sidebar (sections: Pulse / Pipeline / System) and connection-status footer. Wire all existing routes through it.
  3. Refactor pages one at a time in pipeline order: Scrape → Offers → Leads → Outreach → Sequences → Dashboard → Settings.
  4. Delete the manual revenue override Flask route + template + the AI revenue forecast component + the global "+ Asana task" header button. Don't soft-hide them — actually rip them out.
  5. Wire keyboard shortcuts on Outreach last; everything else should work without them.

Don't

  • Don't introduce shadcn, Material, or any other component library that brings its own design opinion. Hand-roll the components.
  • Don't add dark mode yet. One mode, well-tuned.
  • Don't add icons inside copy or buttons unless they're carrying meaning (↗ for "open external", + for "create"). No decorative ✨🚀💡.
  • Don't use box-shadows for emphasis. Hairline borders + sunken backgrounds do the layering.

Acceptance check (eyeball test)

The redesign is done when:

  • Every page reads like a Notion doc on first scroll: title, subtitle, then stacked blocks with breathing room.
  • You can identify any page from a 100px-tall thumbnail by its block layout alone.
  • There is exactly one primary (ink-fill) button visible at any time per page.
  • Settings has three blocks. Not four. Not two.
  • You no longer see "AI revenue forecast" anywhere in the app or codebase.
